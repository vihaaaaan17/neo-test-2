# 02: Operationalization & Telemetry Header Propagation

**What to build:** Enhance the Open Notebook integration client to extract execution context and inject explicit `X-Neosis-Run-ID`, `X-Neosis-Task-ID`, and `X-Neosis-Request-ID` headers into all downstream Open Notebook HTTP requests. This enables domain-level log correlation across service boundaries, supplementing the core OpenTelemetry traces.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Ensure the existing `app/integrations/open_notebook/client.py` captures context identifiers from the request or active task.
- [ ] Inject `X-Neosis-Run-ID`, `X-Neosis-Task-ID`, and `X-Neosis-Request-ID` into the `httpx.AsyncClient` or request headers.
- [ ] Verify that headers are not randomly generated by the client but extracted from the existing Neosis execution context.
- [ ] Write a unit test ensuring the headers are correctly propagated on outgoing requests.

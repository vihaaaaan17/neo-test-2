Research Workspace — Principal Architecture			
Canonical architecture decisions and boundaries. This workbook is intended to be implemented directly and decomposed later into your own subphases.			
			
Topic	Architecture Decision	Class	Status
Goal	One implementable research workspace combining a NotebookLM-style grounded mode and an autonomous deep-research mode over a shared memory + state fabric.	Decision	Locked
Core UX concept	Mode toggle: GROUND for source-grounded research and RESEARCH for autonomous multi-step investigation. Both operate on the same workspace.	Decision	Locked
Knowledge graphs	Two graphs only: Internal KG is exhaustive and operational; Research Output KG is a curated, user-visible semantic projection.	Decision	Locked
Citation graph	Removed as an independent graph. Citation/provenance are fields and relations on evidence/claims, not a separate graph.	Decision	Locked
Memory model	6 logical memory systems; they are behaviors/ownership boundaries, not necessarily six databases.	Decision	Locked
State model	8 state systems; state is mutable workflow/control information, not another copy of the knowledge base.	Decision	Locked
Schema philosophy	Typed core + extensible metadata. Mandatory fields are only those required for identity, ownership, provenance, lifecycle, or graph integrity.	Decision	Locked
Versioning	Git-like commits, branches, diffs and rollback at workspace/research state level, without literally storing every database row in Git.	Decision	Locked
Scratchpad	First-class working-memory surface; items can be promoted to research memory or graph knowledge after validation.	Decision	Locked
Free-tier strategy	Keep the logical architecture provider-agnostic and deploy a small physical stack first; scale individual stores independently.	Decision	Locked
UI scope	UI is intentionally outside this engineering inventory except for integration contracts and user-visible graph/state outputs.	Scope	Locked

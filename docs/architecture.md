# Architecture Overview

NeosisLM is a robust, clean-architecture system designed for autonomous AI research. It heavily leverages provider abstraction and decoupled micro-operations to ensure it scales cleanly from a local machine to a massive cloud deployment.

## The Infrastructure Stack

- **PostgreSQL**: The canonical source of truth for Workspaces, Identity, Sources, Knowledge Memory, and Workflows.
- **Neo4j**: Graph database used for advanced semantic linking (e.g., Output KG). It acts as a projection of truth rather than the single source of truth.
- **Object Storage (S3)**: Used for immutable blobs (uploaded PDFs, export `.zip` or `.parquet` files). Blobs are *never* stored in Postgres.
- **Redis & Arq**: Used for asynchronous background job queueing (parsing, heavy exports, and agent loops) and Pub/Sub notifications.
- **FastAPI**: The highly asynchronous API layer bridging the frontend and the services.

## Core Boundaries

### 1. The Workspace
Everything in NeosisLM is scoped to a `Workspace`. A Workspace represents a distinct "Project" and serves as a strict tenant boundary. Users upload files to a workspace and run autonomous research sessions inside it.

### 2. Knowledge Representation
NeosisLM utilizes a **Six-Memory System**:
1. **Source Memory**: Raw pointers to parsed blobs.
2. **Working Memory**: Ephemeral buffers used during an agent's run.
3. **Episodic Memory**: Summaries of past events.
4. **Knowledge Memory**: The permanent, canonical database of verified facts and claims.
5. **Research Memory**: Long-lived conclusions generated by the agent.
6. **User/Workspace Memory**: Explicit human instructions and configuration.

### 3. Graph Projection
Instead of keeping a single chaotic graph, we maintain:
- **Internal KG**: The raw operational relational data in Postgres.
- **Output KG (Neo4j)**: A curated, user-facing projection mapping semantic relationships (e.g., `SUPPORTS`, `CONTRADICTS`) directly into Neo4j.

## Provider Agnosticism
NeosisLM never hardcodes specific vendors for variable resources:
- **LLMs**: Handled via `LiteLLM`, allowing hot-swapping between Gemini, OpenAI, Anthropic, or Local models.
- **Search**: `Tavily` is used via a `WebSearchTool` abstraction.
- **Storage**: Any S3-compatible service (AWS S3, MinIO, Cloudflare R2) works seamlessly with the `ObjectStoreProtocol`.
